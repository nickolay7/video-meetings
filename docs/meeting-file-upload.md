# PRD: Загрузка файлов встречи

**Дата:** 2026-08-04
**Статус:** draft

## Цель

Участник встречи может прикрепить к встрече файл, чтобы сохранить его на сервере и вернуться к нему позже. Файлы хранятся на локальном диске сервера, отображаются и скачиваются из интерфейса встречи. Эта итерация покрывает хранение и отображение; обработка содержимого — отдельный этап.

## Пользовательские сценарии

- **Пользователь** открывает карточку встречи на главной и нажимает «Файлы» → открывается модальное окно со списком файлов встречи → он видит, какие файлы уже прикреплены.
- **Пользователь** в модальном окне нажимает «Загрузить файл» и выбирает файл → файл отправляется на сервер, сохраняется в папке встречи → появляется в списке с именем, размером, типом и датой загрузки.
- **Пользователь** загружает файл больше 20 МБ → сервер отклоняет загрузку → пользователь видит понятное сообщение об ошибке, список файлов не меняется.
- **Пользователь** нажимает на файл в списке → файл скачивается.

## Скоуп

### В скоупе

- Загрузка файла к конкретной встрече через API (multipart).
- Хранение файлов на локальном диске сервера в структуре по встречам.
- Валидация загрузки: лимит 20 МБ на файл, любые типы файлов.
- Список файлов встречи с метаданными: имя, размер, тип, дата загрузки.
- Скачивание файла.
- Модальное окно «Файлы» на главной странице: кнопка на карточке встречи, список файлов, загрузка.
- Обновление списка сразу после загрузки, без перезагрузки страницы.
- Защита всех эндпоинтов через JWT-аутентификацию.

### Не в скоупе

- Обработка содержимого файлов (извлечение текста, индексация, анализ) — следующий этап.
- Внешнее/облачное хранилище (S3 и аналоги).
- Страница деталей встречи `/meetings/:id` — файлы отображаются в модальном окне.
- Удаление и переименование файлов.
- Права доступа по участникам (сейчас — любой авторизованный пользователь).
- Превью содержимого файлов.

## Технические ограничения

- Хранилище — локальный диск сервера; доступный объём ограничен ресурсами хоста. Учитывать рост файлов при планировании размещения.
- Репозитории API (встречи, пользователи) — in-memory и сбрасываются при перезапуске, при этом файлы на диске переживают перезапуск. Определить поведение «файл есть, метаданных встречи нет» после рестарта.
- Разрешены любые типы файлов — при приёме и выдаче обязательна защита от небезопасных имён и путей (использовать только имя файла, без произвольных путей).
- UI-изменения обязательны к визуальной проверке через Playwright MCP.

## Критерии готовности

1. Авторизованный пользователь может загрузить файл к встрече; файл сохраняется на диск сервера в папке встречи.
2. Загрузка файла более 20 МБ отклоняется с понятным сообщением; файл не появляется в списке.
3. Список файлов встречи отображает имя, размер, тип и дату загрузки.
4. Файл скачивается по ссылке; содержимое совпадает с загруженным.
5. Модальное окно «Файлы» открывается с карточки каждой встречи, показывает список файлов и кнопку загрузки.
6. После успешной загрузки новый файл появляется в списке без перезагрузки страницы.
7. Обращения к эндпоинтам файлов без JWT-токена возвращают 401.
8. Два файла с одинаковым именем сохраняются без перезаписи друг друга.
9. e2e-тесты API покрывают: загрузку, список, скачивание, отказ при превышении лимита, 401 без токена.
10. UI-изменения проверены визуально через Playwright MCP.
