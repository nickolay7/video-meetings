# PRD: Извлечение инсайтов из транскрипции встречи

**Дата:** 2026-08-09
**Статус:** draft

## Цель

Участник встречи может получить структурированную выжимку из аудиорасшифровки (транскрипции): краткое содержание, список задач и принятые решения — без необходимости перечитывать всю расшифровку. Инсайты генерируются автоматически после завершения транскрибации и отображаются в карточке встречи рядом с транскрипцией.

## Пользовательские сценарии

- **Пользователь** открывает страницу встречи, где есть завершённая транскрипция → видит три блока: «Саммари», «Задачи», «Решения»; текст транскрипции также доступен.
- **Пользователь** открывает страницу встречи, где транскрипция ещё не завершена → блоки инсайтов не отображаются (или отображаются с индикатором «Генерируется…»).
- **Пользователь** смотрит блок «Саммари» → видит 3–5 предложений, сжато описывающих суть встречи, ключевые обсуждения и выводы.
- **Пользователь** смотрит блок «Задачи» → видит пронумерованный список задач, каждая с текстом и (если упомянут ответственный) с именем или ролью исполнителя.
- **Пользователь** смотрит блок «Решения» → видит пронумерованный список принятых решений с формулировкой каждого.
- **Пользователь** возвращается к той же встрече позже → инсайты сохранились и отображаются без повторной генерации.
- **Пользователь** загружает новую версию файла (или перезапускает транскрибацию после ошибки) → инсайты перегенерируются автоматически.

## Скоуп

### В скоупе

- Автоматическая генерация трёх типов инсайтов после завершения транскрибации: саммари, задачи, решения.
- Генерация через Claude Agent SDK (локальный вызов модели, без внешних HTTP-сервисов).
- Сохранение инсайтов в том же хранилище, что и транскрипция (in-memory; при перезапуске — сброс, как и у самой транскрипции).
- API-эндпоинты для получения инсайтов по встрече/файлу (под JWT-защитой).
- Отображение трёх блоков в карточке встречи после завершения транскрибации.
- Перегенерация инсайтов при повторной транскрибации файла.
- Покрытие e2e-тестами: генерация замоканным SDK, получение инсайтов, 401 без токена, поведение до завершения транскрипции.

### Не в скоупе

- Выбор пользователем модели для генерации инсайтов (всегда Claude, настраивается через конфигурацию).
- Ручной запуск генерации инсайтов отдельно от транскрибации (инсайты генерируются автоматически; если транскрипция уже есть — перезапуск транскрибации триггерит перегенерацию).
- Редактирование или удаление отдельных инсайтов (только просмотр; при необходимости — перезапуск транскрибации целиком).
- Таймкоды, ссылки на фрагменты записи в инсайтах.
- Экспорт инсайтов (PDF, копирование).
- Мгновенная генерация до завершения транскрибации (ожидание полного текста обязательно).
- Резервный генератор при недоступности Claude (ошибка пробрасывается пользователю как статус `failed` инсайтов).

## Технические ограничения

- Генерация инсайтов зависит от завершённой транскрипции — запускается только после того, как текст готов.
- Используется Claude Agent SDK (уже интегрирован в `ClaudeAgentService`), который вызывает локальный CLI Claude Code. Аутентификация — через `ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN` из `.env`. Таймаут — `CLAUDE_TIMEOUT_MS` (по умолчанию 120 с); при превышении генерация падает с ошибкой.
- Объём текста транскрипции может быть большим (длинные встречи) — учитывать при формировании промпта и таймауте.
- Хранилище инсайтов — in-memory репозиторий, как у транскрипции и файлов: при перезапуске сервера данные теряются, кнопка повторной транскрибации снова доступна, инсайты генерируются заново.
- e2e-тесты не вызывают реальный Claude Agent SDK — SDK мокается, как в `claude.e2e-spec.ts`.
- UI-изменения обязательны к визуальной проверке через Playwright MCP.

## Критерии готовности

1. После завершения транскрибации файла автоматически запускается генерация инсайтов: статус инсайтов проходит `queued` → `processing` → `completed`.
2. API `GET /meetings/:id/files/:fileId/insights` возвращает `{ summary, actionItems, decisions }` при статусе `completed`; до завершения — 409 с сообщением.
3. API `GET /meetings/:id/files/:fileId/insights/status` возвращает статус: `none`, `queued`, `processing`, `completed`, `failed`.
4. В карточке встречи после завершения генерации отображаются три блока: «Саммари», «Задачи», «Решения»; при статусе `failed` — сообщение об ошибке.
5. Если транскрипция не завершена или не запущена, блоки инсайтов не отображаются (или скрыты).
6. При повторной транскрибации файла (после `failed` или `completed`) инсайты перегенерируются; старые данные заменяются.
7. Обращения к эндпоинтам инсайтов без JWT-токена возвращают 401.
8. e2e-тесты покрывают: запуск генерации (замоканный SDK), получение статуса, получение инсайтов, 401 без токена.
9. UI-изменения проверены визуально через Playwright MCP.
