# PRD: Профиль пользователя (просмотр, редактирование, аватар, смена пароля)

**Дата:** 2026-08-05
**Статус:** draft

## Цель

Авторизованный пользователь может посмотреть и отредактировать свой профиль: задать имя, загрузить аватар, сменить пароль. Аватар и имя отображаются пользователю на главной странице после входа. Профиль даёт пользователю контроль над собственными данными аккаунта.

## Пользовательские сценарии

- **Пользователь** логинится и попадает на главную → в шапке отображается его аватар и имя (или email как запасной вариант) → он видит, под каким профилем вошёл.
- **Пользователь** открывает страницу профиля `/profile` → видит свои данные: аватар, имя, email → переходит по ссылке на редактирование.
- **Пользователь** открывает страницу редактирования `/profile/edit` → меняет имя → изменения сохраняются и отображаются на странице профиля и в шапке главной; если имя очистить, вместо него отображается email.
- **Пользователь** на странице редактирования загружает аватар (файл изображения) → аватар сохраняется на сервере и заменяет прежний на странице профиля и в шапке главной.
- **Пользователь** на странице редактирования меняет пароль: вводит старый и новый пароль → старый пароль проверяется, новый сохраняется → при следующем входе действует новый пароль.
- **Пользователь** вводит неверный старый пароль → сервер отклоняет смену пароля → пользователь видит понятное сообщение об ошибке, пароль не меняется.

## Скоуп

### В скоупе

- Поле `name` у пользователя; необязательное, заполняется при регистрации (новая форма регистрации включает необязательное имя, email остаётся логином). Если имя не указано, для отображения используется email.
- API профиля (защищено JWT):
  - получение своего профиля: id, имя, email, аватар;
  - обновление имени;
  - загрузка аватара (multipart, файл изображения);
  - выдача загруженного аватара для отображения;
  - смена пароля с проверкой старого пароля (старый + новый).
- Смена пароля проходит только при корректном старом пароле.
- Страница `/profile` — просмотр профиля (аватар, имя, email) и переход к редактированию.
- Страница `/profile/edit` — изменение имени, загрузка аватара, смена пароля (старый → новый).
- Отображение аватара и имени пользователя в шапке главной страницы после входа (имя или email как fallback).
- Валидация аватара: только типы изображений, лимит 5 МБ на файл.
- Хранение аватара на локальном диске сервера в структуре по пользователям.
- Обращения к эндпоинтам профиля без JWT-токена возвращают 401.

### Не в скоупе

- Обработка изображения на сервере: кадрирование, изменение размера, конвертация, создание превью разных форматов — аватар хранится как загружен.
- Множественные/версионные аватары и история изменений.
- Смена email.
- Восстановление пароля по email / «забыли пароль».
- Удаление аккаунта.
- Профили других пользователей и просмотр чужих профилей — только свой профиль.
- Отображение аватара вне шапки главной (карточки встреч, список участников и т. п.).

## Технические ограничения

- Репозиторий пользователей in-memory, сбрасывается при перезапуске. Определить поведение аватара на диске после рестарта, когда метаданные (или сам пользователь) уже отсутствуют.
- Хранилище — локальный диск сервера; объём ограничен ресурсами хоста (по образцу файлов встреч, `apps/api/uploads/`).
- Аватар — изображение, но при приёме и выдаче обязательно защита от небезопасных имён и путей (использовать контролируемое имя хранилища, опираясь на проверенный тип, а не на пользовательское имя).
- Валидация типа аватара по фактическому содержимому (MIME), не только по расширению. Лимит размера 5 МБ.
- При хранении паролей используется хеширование (по текущей схеме auth); смена пароля не должна ослаблять её.
- UI-изменения обязательны к визуальной проверке через Playwright MCP.

## Критерии готовности

1. Поле `name` у пользователя необязательное; при регистрации имя может быть указано или опущено. Если имя не задано, в интерфейсе вместо него отображается email.
2. Авторизованный пользователь может получить свой профиль через API; без JWT-токена возвращается 401.
3. Пользователь может изменить имя; новое имя отображается на странице профиля и в шапке главной после загрузки страницы.
4. Пользователь может загрузить аватар-изображение; аватар сохраняется на диске сервера в структуре по пользователям и заменяет прежний при повторной загрузке.
5. Загрузка файла не-изображения или файла больше 5 МБ отклоняется с понятным сообщением; прежний аватар не теряется.
6. Загруженный аватар отображается на странице профиля и в шапке главной страницы пользователя.
7. Смена пароля с верным старым паролем проходит успешно; новый пароль действует при следующем входе.
8. Смена пароля с неверным старым паролем отклоняется с понятным сообщением; пароль не меняется.
9. e2e-тесты API покрывают: получение профиля, обновление имени, загрузку аватара (включая отказ при неверном типе/размере), смену пароля (включая отказ при неверном старом), 401 без токена.
10. UI-изменения проверены визуально через Playwright MCP.
