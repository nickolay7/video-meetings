# PRD: Транскрибация файлов встречи

**Дата:** 2026-08-08
**Статус:** draft

## Цель

Участник встречи может получить текстовую расшифровку аудио- или видеозаписи (MP4/MP3), прикреплённой к встрече: он запускает транскрибацию по кнопке, а результат — текст записи — доступен в интерфейсе встречи. Распознавание выполняется локально через Whisper с лёгкой моделью, без внешних сервисов.

## Пользовательские сценарии

- **Пользователь** открывает модальное окно «Файлы» встречи → у файлов MP4/MP3 видит кнопку «Транскрибировать», у файлов других типов кнопки нет.
- **Пользователь** нажимает «Транскрибировать» → файл ставится в очередь, в списке отображается статус: «В очереди» → «Транскрибация…» → «Готово», без перезагрузки страницы.
- **Пользователь** после завершения открывает транскрипцию → видит полный текст записи (без таймкодов).
- **Пользователь** видит, что транскрибация завершилась ошибкой → статус «Ошибка» с сообщением, по повторному клику обработка запускается заново.
- **Пользователь** ставит в очередь несколько файлов подряд → файлы обрабатываются по очереди, статусы каждого не путаются.
- **Пользователь** во время транскрибации продолжает работать с файлами встречи (загружать, скачивать) → операции не блокируются.

## Скоуп

### В скоупе

- Кнопка «Транскрибировать» для файлов MP4/MP3 в модальном окне «Файлы».
- Запуск транскрибации через API с фоновой обработкой и очередью.
- Статусы транскрибации: «В очереди», «Транскрибация…», «Готово», «Ошибка»; отображение в списке файлов.
- Распознавание речи локальным Whisper, лёгкая модель (base/low, настраивается через конфигурацию), автоопределение языка.
- Хранение текста результата в хранилище метаданных (in-memory, как файлы и встречи).
- Просмотр текста транскрипции в интерфейсе встречи.
- Повторный запуск транскрибации после ошибки.
- Последовательная обработка: один файл транскрибируется за раз, остальные ждут в очереди.
- Защита эндпоинтов через JWT-аутентификацию.

### Не в скоупе

- Таймкоды, разбивка на сегменты (SRT), навигация по записи.
- Транскрибация форматов, отличных от MP4/MP3.
- Повторная транскрибация уже завершённых файлов (после «Готово» кнопка скрыта).
- Отмена запущенной транскрибации.
- Выбор модели пользователем в интерфейсе.
- Облачная транскрибация (OpenAI API и аналоги) — только локальная.
- GPU-ускорение.
- Долговременное/внешнее хранилище результата транскрибации.
- Права доступа по участникам (как у файлов — любой авторизованный пользователь).

## Технические ограничения

- Whisper работает локально на сервере; на CPU транскрибация медленная — длинные записи обрабатываются долго, поэтому обработка асинхронная и только одна за раз.
- Лёгкая модель (base/low) выбрана для экономии ресурсов сервера; первый запуск требует загрузки модели на диск (~140 МБ для base) — учесть объём.
- Хранилище результата — in-memory репозиторий, как у файлов и встреч: при перезапуске сервера статус и текст теряются, файл на диске остаётся, кнопка снова доступна. Поведение после рестарта задокументировать.
- e2e-тесты не тянут модель Whisper: транскрибатор в тестах мокается.
- UI-изменения обязательны к визуальной проверке через Playwright MCP.

## Критерии готовности

1. В модальном окне «Файлы» у файлов MP4/MP3 отображается кнопка «Транскрибировать»; у файлов других типов кнопки нет.
2. После клика по кнопке статус файла проходит «В очереди» → «Транскрибация…» → «Готово» и обновляется в списке без перезагрузки страницы.
3. После завершения текст транскрипции доступен для просмотра; при распознавании тестового MP3 с известной речью текст соответствует содержанию записи.
4. При ошибке транскрибации отображается статус «Ошибка» с сообщением; повторный клик запускает обработку заново.
5. Файлы, поставленные в очередь подряд, обрабатываются последовательно; статусы файлов не перепутываются.
6. Во время транскрибации работают загрузка, скачивание и список файлов — сервер не блокирует запросы.
7. После успешного завершения кнопка «Транскрибировать» для файла скрыта.
8. Обращения к эндпоинтам транскрибации без JWT-токена возвращают 401.
9. e2e-тесты API покрывают: запуск транскрибации, получение статуса, получение текста, 401 без токена; транскрибатор замокан.
10. UI-изменения проверены визуально через Playwright MCP.
