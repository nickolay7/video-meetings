# План: Загрузка файлов встречи

**PRD:** [meeting-file-upload.md](./meeting-file-upload.md)
**Дата:** 2026-08-04

## Фаза 1: Backend — загрузка и хранение файлов

**Цель:** файл можно загрузить к встрече, он сохраняется на диск сервера в папке встречи; действует лимит 20 МБ и защита от небезопасных имён; эндпоинт защищён JWT.

**Затрагивает:** `backend`

**Задачи:**

1. Создать модуль `Files`: контроллер, сервис, репозиторий метаданных (in-memory), сущность `MeetingFile` (id, meetingId, originalName, storedName, size, mimeType, uploadedAt).
2. `POST /meetings/:id/files` — приём multipart-файла и сохранение на диск в `uploads/<meetingId>/`; 404 при несуществующей встрече.
3. Валидация: лимит 20 МБ на файл; использовать только имя файла, без произвольных путей.
4. Уникальные имена на диске — два файла с одинаковым именем не перезаписывают друг друга.
5. Защита эндпоинтов через `JwtAuthGuard` (401 без токена); задокументировать поведение после перезапуска: метаданные in-memory (как у встреч) сбрасываются, осиротевшие файлы на диске игнорируются.

**Критерий готовности:** загрузка сохраняет файл на диск и создаёт запись метаданных; файл больше 20 МБ отклоняется с понятным ответом; одинаковые имена не перезаписываются; без токена — 401.

## Фаза 2: Backend — список, скачивание и e2e-тесты

**Цель:** файлы встречи можно перечислить и скачать; поведение API закреплено e2e-тестами.

**Затрагивает:** `backend`, `test`

**Задачи:**

1. `GET /meetings/:id/files` — список файлов встречи с метаданными (имя, размер, тип, дата загрузки).
2. `GET /meetings/:id/files/:fileId/download` — скачивание файла с корректным содержимым и именем; 404 при отсутствии файла.
3. e2e-тесты: загрузка, список, скачивание, отказ при превышении лимита, 401 без токена.
4. e2e-тесты: два файла с одинаковым именем сохраняются оба.

**Критерий готовности:** список и скачивание работают; содержимое скачанного файла совпадает с загруженным; e2e-набор зелёный и покрывает сценарии из критерия 9 PRD.

## Фаза 3: Frontend — модальное окно «Файлы»

**Цель:** пользователь видит файлы встречи и может загрузить и скачать их прямо с главной страницы, без перезагрузки.

**Затрагивает:** `frontend`

**Задачи:**

1. Кнопка «Файлы» на карточке встречи, открывающая модальное окно.
2. Модальное окно: список файлов (имя, размер, тип, дата) и кнопка «Загрузить файл».
3. Загрузка: индикатор состояния; новый файл появляется в списке сразу после успеха, без перезагрузки страницы.
4. Обработка ошибок: понятное сообщение при превышении лимита 20 МБ; список не меняется.
5. Скачивание файла по клику на элемент списка.

**Критерий готовности:** модальное окно открывается с карточки каждой встречи; после загрузки файл появляется в списке без перезагрузки; ошибка лимита отображается; файл скачивается; UI-изменения проверены визуально через Playwright MCP (критерий 10 PRD).
