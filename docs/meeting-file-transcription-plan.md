# План: Транскрибация файлов встречи

**PRD:** [meeting-file-transcription.md](./meeting-file-transcription.md)
**Дата:** 2026-08-08

## Фаза 1: Backend — сервис транскрибации и очередь

**Цель:** на сервере появляется возможность транскрибировать MP4/MP3-файлы локальным Whisper в фоне — по одному файлу за раз, со статусами и результатом, без блокировки остальных запросов.

**Затрагивает:** `backend`

**Задачи:**

1. Модуль `Transcription`: сервис-обёртка над локальным Whisper (лёгкая модель base/low через конфигурацию, автоопределение языка), репозиторий метаданных (in-memory, по образцу `FilesRepository`) и сущность транскрипции: `fileId`, `meetingId`, `status`, `error`, `text`.
2. Очередь с последовательной обработкой: один файл транскрибируется за раз, остальные ждут; статус проходит «В очереди» → «Транскрибация…» → «Готово».
3. Обработка ошибок: при сбое Whisper статус «Ошибка» с сообщением; файл снова можно поставить в очередь.
4. Ограничение форматов: транскрибируются только MP4/MP3, остальные форматы отклоняются с понятным ответом.
5. Первый запуск загружает модель Whisper на диск (~140 МБ для base) — путь и модель настраиваются через конфигурацию; поведение после перезапуска задокументировать (метаданные in-memory сбрасываются, кнопка снова доступна).

**Критерий готовности:** транскрибация запускается, обрабатывает файл в фоне, статусы проходят жизненный цикл, ошибка фиксируется в статусе «Ошибка», формат не-MP4/MP3 отклоняется, файлы из очереди не перепутываются, остальные запросы не блокируются.

## Фаза 2: Backend — API-эндпоинты и e2e-тесты

**Цель:** поведение транскрибации доступно через защищённый API и закреплено e2e-тестами с замоканным транскрибатором.

**Затрагивает:** `backend`, `test`

**Задачи:**

1. Контроллер транскрибации под `JwtAuthGuard` (401 без токена, как у `FilesController`): `POST /meetings/:id/files/:fileId/transcribe` — постановка файла в очередь; 404 при несуществующем файле/встрече, отклонение не-MP4/MP3, отклонение повторного запуска завершённого файла.
2. `GET /meetings/:id/files/:fileId/transcription/status` — текущий статус транскрибации файла.
3. `GET /meetings/:id/files/:fileId/transcription` — текст результата при статусе «Готово»; понятный ответ до завершения.
4. e2e-тесты с замоканным транскрибатором: запуск, получение статуса, получение текста, последовательная обработка очереди, 401 без JWT-токена.
5. Ручная проверка реального распознавания: тестовый MP3 с известной речью → полученный текст соответствует содержанию записи (вне e2e-набора, чтобы не тянуть модель).

**Критерий готовности:** e2e-набор зелёный и покрывает критерий 9 PRD; эндпоинты без токена возвращают 401; тестовый MP3 распознан с текстом, соответствующим содержанию (критерий 3 PRD).

## Фаза 3: Frontend — кнопка «Транскрибировать» и статусы

**Цель:** пользователь видит у MP4/MP3-файлов кнопку «Транскрибировать», запускает транскрибацию и наблюдает статус в списке файлов без перезагрузки страницы.

**Затрагивает:** `frontend`

**Задачи:**

1. Кнопка «Транскрибировать» у файлов MP4/MP3 в модальном окне «Файлы»; у файлов других типов кнопки нет.
2. По клику — постановка в очередь и отображение статусов «В очереди» / «Транскрибация…» / «Готово» / «Ошибка» в списке; обновление статуса без перезагрузки (опрос API).
3. Обработка ошибок: статус «Ошибка» с сообщением; повторный клик запускает транскрибацию заново.
4. После статуса «Готово» кнопка «Транскрибировать» для файла скрывается.
5. Проверка, что во время транскрибации работают загрузка, скачивание и список файлов — сервер не блокируется.

**Критерий готовности:** кнопка и статусы соответствуют критериям 1, 2, 4, 5, 6, 7 PRD; визуальная проверка через Playwright MCP.

## Фаза 4: Frontend — просмотр текста транскрипции

**Цель:** пользователь может прочитать полный текст расшифровки завершённой записи.

**Затрагивает:** `frontend`

**Задачи:**

1. Кнопка открытия транскрипции у завершённого файла (например, «Показать транскрипцию»).
2. Отображение полного текста записи в модальном окне «Файлы».
3. Финальная визуальная проверка всех UI-изменений через Playwright MCP (критерий 10 PRD).

**Критерий готовности:** текст транскрипции доступен для просмотра у завершённых файлов (критерий 3 PRD); UI-изменения фичи проверены визуально через Playwright MCP.
