# План: Извлечение инсайтов из транскрипции встречи

**PRD:** [transcription-insights.md](./transcription-insights.md)
**Дата:** 2026-08-09

---

## Фаза 1: Бэкенд — слой данных и API инсайтов

**Цель:** Создать хранилище для инсайтов (summary, actionItems, decisions) и API-эндпоинты для получения статуса и данных. На этой фазе генерация ещё не подключена — инсайты можно будет записать вручную (через тесты) и прочитать через API.

**Затрагивает:** `backend`

**Задачи:**

1. Создать `InsightsModule` с репозиторием (in-memory, по образцу `TranscriptionRepository`) и сущностью `MeetingInsights` (поля: `fileId`, `meetingId`, `status`, `summary?`, `actionItems[]`, `decisions[]`, `error?`, `createdAt`).
2. Реализовать `InsightsController` с эндпоинтами:
   - `GET /meetings/:id/files/:fileId/insights/status` — возвращает статус (`none`/`queued`/`processing`/`completed`/`failed`) и error при `failed`.
   - `GET /meetings/:id/files/:fileId/insights` — возвращает `{ summary, actionItems, decisions }` при `completed`; 409 до завершения.
3. Весь контроллер под `@UseGuards(JwtAuthGuard)` — 401 без токена.
4. Написать e2e-тесты: получение статуса `none` (транскрипция есть, инсайтов нет), запись через репозиторий → получение инсайтов, 401 без токена.

**Критерий готовности:**

- API отдаёт статус `none` для файла без инсайтов; после записи в репозиторий — `completed` с данными; 401 без токена; 409 до завершения. Всё покрыто e2e.

## Фаза 2: Бэкенд — генерация инсайтов через Claude при завершении транскрибации

**Цель:** Автоматически генерировать summary, action items и decisions из текста транскрипции через Claude Agent SDK после завершения транскрибации. Инсайты сохраняются в репозиторий, созданный в Фазе 1, и перегенерируются при повторной транскрибации.

**Затрагивает:** `backend`

**Задачи:**

1. Создать `InsightsGeneratorService` с методом `generate(fileId, meetingId, transcriptionText)`, который:
   - Формирует промпт для Claude: запросить JSON со структурой `{ summary, actionItems: [{ text, assignee? }], decisions: [{ text }] }`.
   - Вызывает `ClaudeAgentService.run()` (уже существует).
   - Парсит JSON-ответ, сохраняет в `InsightsRepository` со статусом `completed`; при ошибке — `failed` с сообщением.
2. Интегрировать генерацию в `TranscriptionService`: после того как статус транскрибации стал `completed`, запустить `InsightsGeneratorService.generate()` (без ожидания — параллельно, чтобы не блокировать очередь транскрибации). Статус инсайтов: `queued` → `processing` → `completed`/`failed`.
3. При повторной транскрибации файла старые инсайты сбрасываются (status = `queued`, поля очищаются).
4. Написать e2e-тесты: замокать `ClaudeAgentService`, проверить, что после завершения транскрибации инсайты сохраняются с правильными данными; при ошибке Claude — статус `failed`; перегенерация при повторной транскрибации.

**Критерий готовности:**

- После завершения транскрибации инсайты автоматически появляются со статусом `completed` и корректными данными. При ошибке — `failed`. При повторной транскрибации — старые инсайты заменяются. Всё покрыто e2e с замоканным SDK.

## Фаза 3: Фронтенд — отображение инсайтов в карточке встречи

**Цель:** Пользователь видит три блока (Саммари, Задачи, Решения) в карточке встречи после завершения генерации инсайтов. Статусы отображаются корректно на всех этапах: генерация, готово, ошибка, нет данных.

**Затрагивает:** `frontend`

**Задачи:**

1. Добавить API-клиент для эндпоинтов инсайтов (статус + данные) на фронтенде.
2. В карточке встречи добавить блок «Инсайты встречи», который:
   - При статусе `none` — скрыт (или показывает сообщение «Транскрипция ещё не обработана»).
   - При статусе `queued`/`processing` — показывает индикатор «Генерируем инсайты…».
   - При статусе `completed` — отображает три секции: «Саммари» (текст), «Задачи» (нумерованный список с assignee, если есть), «Решения» (нумерованный список).
   - При статусе `failed` — показывает сообщение об ошибке.
3. Реализовать polling статуса (раз в 2–3 с) после завершения транскрибации, пока инсайты не будут готовы или не упадут с ошибкой.
4. Визуально проверить через Playwright MCP: все состояния (загрузка, готово, ошибка, нет данных).

**Критерий готовности:**

- В карточке встречи отображаются три блока с данными после генерации; индикатор загрузки — во время генерации; сообщение об ошибке — при сбое; блоки скрыты, если транскрипция не завершена. UI проверен через Playwright.
