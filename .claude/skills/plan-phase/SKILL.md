# Plan Generator Skill

## Метаданные

- **name**: `plan`
- **description**: разбивает PRD на фазы реализации; используется, когда PRD готов и нужно составить план разработки с независимыми фазами.

## Поведение скилла

Скилл принимает аргумент — название или путь к PRD-файлу (например, имя фичи или `docs/file-upload.md`) — и на его основе создаёт план реализации.

1. **Чтение PRD**
   Скилл ищет файл PRD в папке `docs` (или использует переданный путь). Если файл не найден, запрашивает уточнение.

2. **Анализ и структурирование**
   На основе содержания PRD скилл выделяет ключевые требования, пользовательские сценарии и критерии готовности, чтобы разбить работу на логические фазы.

3. **Создание плана**
   Сгенерированный план сохраняется в папку `docs` с именем в формате:
   `<название-фичи>-plan.md` (например, `file-upload-plan.md`).

4. **Проверка полноты**
   Если PRD не содержит достаточной информации (неясны критерии, скоуп, сценарии), скилл задаёт уточняющие вопросы перед созданием плана.

---

## Структура документа-плана

Документ плана включает:

- **Заголовок**: название фичи (берётся из PRD).
- **PRD**: ссылка или название исходного PRD-файла.
- **Дата**: текущая дата.
- **Блоки фаз** — для каждой фазы:
  - **Номер и название фазы** (подзаголовок)
  - **Цель** — что даёт эта фаза (ценность для пользователя или команды).
  - **Затрагивает** — области системы: `backend`, `frontend`, `database`, `infrastructure` и т. д.
  - **Задачи** — список конкретных задач (не более пяти на фазу).
  - **Критерий готовности** — конкретное условие, при котором фаза считается завершённой.

---

## Правила для скилла при чтении PRD

1. **Внимательно читать PRD** — извлекать все сценарии, скоуп, ограничения и критерии готовности.
2. **Покрывать все критерии готовности** из PRD — в совокупности фазы должны гарантировать выполнение каждого критерия.
3. **Не добавлять задачи, которых нет в PRD** — план строго следует описанным требованиям.
4. **Если PRD неполный** — задать уточняющие вопросы до создания плана (например, уточнить скоуп, критерии или приоритеты).

---

## Пример использования

**Запрос:**

> `plan file-upload`

**Действие:**
Скилл находит `docs/file-upload.md`, анализирует его и создаёт `docs/file-upload-plan.md` с фазами, например:

- Фаза 1: Базовая загрузка файлов (frontend, backend)
- Фаза 2: Валидация и обработка ошибок
- Фаза 3: Интеграция с хранилищем

Каждая фаза содержит цели, задачи и чёткий критерий готовности.

---

## Зачем нужен план

План превращает абстрактный PRD в дорожную карту, позволяя команде:

- Оценивать сроки и ресурсы для каждой фазы.
- Разрабатывать итеративно, получая работающие инкременты.
- Проверять прогресс по конкретным критериям.
- Синхронизировать работу разных специалистов (бэкенд, фронтенд, DevOps).
